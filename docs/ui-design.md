# 界面设计规范

更新：2026-11-15。本文定义第二轮界面优化的设计 token、页面结构、组件规范与改造清单，供后续实现和评审使用。

与 [需求与约定](requirements.md) 冲突时以需求为准；本文不修改任何已确认的业务规则、信息架构和接口协议。标注“待确认”的条目需要用户确认后才实施，不能直接当成已确定需求。

## 目标与边界

### 目标

- 公开站建立“开发者工具可信感 + 媒体产品展示力”，控制台优先信息密度和操作效率。
- 用统一的 token、页面模板和组件规范消除“所有页面长得一样”的模板感。
- 在不引入新依赖、不改变已确认结构的前提下，提升首屏表达、数据可读性和交互反馈。

### 约束

- 继续使用 Vue 3、Element Plus 和 `@element-plus/icons-vue`；不引入新的组件库、主题库、图表库、动画库或字体 CDN。
- 中文正文使用系统字体；等宽字体只用于 ID、价格、token 数、代码和状态值。
- 三态主题必须同时设计，不能只调整亮色。
- 账务金额仍以八位小数存储和计算；公开页按“价格显示”缩写，完整八位保留在详情中。
- 官网与控制台继续共用前端工程，但保留两套密度和留白。
- 已确认的菜单顺序、文档章节顺序、表格外框规则、分页位置等保持不变。

### 非目标

- 不重做信息架构，不新增业务页面，不做网页创作台。
- 不为了“高级感”使用大面积渐变、玻璃拟态、发光边框。
- 不把控制台改造成 marketing 页面。
- 不为单一页面引入独立设计语言。

## 设计原则

1. **信息优先**：装饰必须服务于理解、比较或操作，不能只做视觉填充。
2. **一个主操作**：每个页面或卡片区域只保留一个主 CTA，其余操作降级为次级或图标。
3. **数字可扫读**：金额、价格、token、ID 使用等宽和 tabular-nums；重要数字放大，噪声数字缩小。
4. **公开站留白，控制台紧凑**：同一组件在两套布局中使用不同密度，不强行统一。
5. **状态不只靠颜色**：状态必须同时有文字或图标；颜色只做辅助。
6. **动效表达因果**：只用于进入、复制、加载、展开等有明确原因的变化，不做循环装饰动画。
7. **中文优先**：字号、行高和断行按中文可读性设计，不照搬西文 landing page 的字距和行宽。

## Design Tokens

实现时集中维护在 `frontend/src/assets/main.css` 的 `:root` 与 `html.dark`，组件内不再新增散落的十六进制颜色、圆角、阴影和过渡时长。

保留现有品牌绿 `#147d64`（暗色 `#65c6a8`）。绿色只用于品牌、主操作、可调用/成功信号和焦点态，不作为大面积背景。

| `--app-surface` | `#ffffff` | `#202325` | 卡片、表格、顶栏 |
| `--app-surface-raised` | `#ffffff` | `#252a2c` | 浮层、弹窗、hover 卡片 |
| `--app-surface-sunken` | `#f3f5f6` | `#16191b` | 筛选区、代码块底、嵌套区域 |
| `--app-border` | `#e5e8eb` | `#353b3f` | 常规分隔线 |
| `--app-border-strong` | `#cfd5da` | `#4a5258` | 输入框、可聚焦边界 |
| `--app-text` | `#24282b` | `#e4e7e8` | 正文与标题 |
| `--app-muted` | `#636c74` | `#a5adb4` | 次要说明 |

| 状态 | 亮色前景 | 亮色底色 | 暗色前景 | 暗色底色 |
| --- | --- | --- | --- | --- |

使用规则：

- 可点击文字、链接、主按钮使用品牌绿；删除、失败使用失败色；提示、待核实使用警告色。
- 不新增第二个品牌强调色；需要区分时优先使用字重、底色和间距。
- 组件内禁止新增十六进制颜色；确需临时颜色时先补 token 并记录原因。
- 暗色模式不直接反色，需单独校准 surface 与边框对比。

### 字体与排版

字体栈保持不变：

```text
-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
"Microsoft YaHei", sans-serif
```

不加载外部 Web Font。代码、ID、价格、token 数继续使用：

```text
"SFMono-Regular", Consolas, "Liberation Mono", monospace
```

| Token | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `--text-display` | 56 / 64 | 首页主标题（桌面） |
| `--text-display-sm` | 36 / 44 | 首页主标题（手机） |
| `--text-h1` | 32 / 40 | 页面标题（公开站） |
| `--text-h1-console` | 28 / 36 | 页面标题（控制台） |
| `--text-h2` | 24 / 32 | 区块标题 |
| `--text-h3` | 18 / 26 | 卡片标题、文档小节 |
| `--text-body` | 15 / 26 | 公开站正文 |
| `--text-body-console` | 14 / 22 | 控制台正文 |
| `--text-small` | 13 / 20 | 辅助说明、表格次要列 |
| `--text-micro` | 12 / 18 | 标签、时间、单位 |
| `--text-code` | 13 / 20 | 代码、ID、价格 |

规则：

- 字重只使用 400、500、600、650；不使用 700 以上，避免中文发虚。
- 正文最小 12px；手机端表单输入保持 16px，避免 iOS 自动缩放。
- 标题最多两行；长标题使用 `overflow-wrap: anywhere`，不用省略号遮住关键信息。
- 数字统一 `font-variant-numeric: tabular-nums`；金额、价格、ID 使用等宽字体。
- 行宽控制在 60–75 个中文字符以内；文档正文最大宽度约 72ch。

| --- | --- | --- |

| `--space-2` | 8px | 紧凑控件间距 |
| `--space-3` | 12px | 表单行内、卡片内小分组 |
| `--space-4` | 16px | 常规组件间距 |
| `--space-5` | 20px | 卡片内边距（紧凑） |
| `--space-6` | 24px | 卡片内边距、区块间距 |
| `--space-8` | 32px | 页面区块间距 |
| `--space-10` | 40px | 公开站内容边距 |
| `--space-12` | 48px | 页面底部留白 |
| `--space-16` | 64px | 公开站区块上下留白 |
| `--space-20` | 80px | 首页区块留白（桌面） |

页面密度：

- 公开站：内容最大宽度 1200px，桌面左右 40px，区块上下 64–96px；手机左右 18px。
- 控制台：主内容内边距 28px 24px 48px；卡片内边距 20–24px；表格单元格纵向 16px。
- 管理表单：桌面两列，手机单列；列间距 20px。

### 圆角

| Token | 值 | 用途 |
| --- | --- | --- |
| `--radius-sm` | 4px | Tag、chip、参数标签 |
| `--radius-md` | 6px | 按钮、输入框、导航项 |
| `--radius-lg` | 8px | 卡片、表格外框、代码块 |
| `--radius-xl` | 12px | 弹窗、首页 feature 卡 |
| `--radius-pill` | 999px | 状态 pill、分段控件 |

不再新增 10px 等临时圆角；同类元素使用同一 token。

### 阴影

| Token | 值 | 用途 |
| --- | --- | --- |
| `--shadow-1` | `0 1px 2px rgba(16,24,40,.04)` | 卡片 hover、轻浮层 |
| `--shadow-2` | `0 8px 24px rgba(16,24,40,.08)` | 弹窗、Popover、Drawer |

- 公开站以边框和留白为主，阴影只在 hover 和浮层使用。
- 暗色模式降低阴影权重，改用 `--app-surface-raised` 与 `--app-border-strong` 表达层级。

### 动效

| Token | 值 | 用途 |
| --- | --- | --- |
| `--duration-fast` | 120ms | hover、按下、复制反馈 |
| `--duration-base` | 180ms | 卡片进入、展开、状态切换 |
| `--duration-slow` | 240ms | 弹窗、Drawer、页面过渡 |
| `--ease-out` | `cubic-bezier(.2,0,0,1)` | 默认缓动 |

规则：

- 只动画 `opacity`、`transform`、`color`、`background-color`，不动画宽度、高度和 top/left。
- 不播放入口循环动画；不做视差和鼠标跟随。
- 必须保留 `prefers-reduced-motion: reduce` 的全局降级。
- 加载超过 500ms 的信息区域使用骨架屏，不用持续旋转的整页 loading。

### 断点与栅格

| 断点 | 用途 |
| --- | --- |
| `375px` | 最小手机宽度 |
| `560px` | 手机布局切换（现有） |
| `900px` | 控制台侧栏收起、公开导航折叠（现有） |
| `1100px` | 四列统计转两列（现有） |
| `1440px` | 大屏内容上限参考 |

- 公开站内容宽度 1200–1280px；控制台内容铺满可用宽度。
- 不允许横向滚动；表格在窄屏改为卡片列表或列优先级隐藏。
- 断点沿用现有实现，第二轮不新增断点，只统一写法。

### 层级

| 层级 | 值 | 用途 |
| --- | --- | --- |
| 基础 | 0 | 页面内容 |
| 吸顶 | 100 | 公开站头部 |
| 浮层 | 2000 | Popover、Dropdown |
| 弹窗 | 2500 | Dialog、Drawer |
| 消息 | 3000 | Message、通知 |
| 跳转链接 | 3100 | Skip link |

Element Plus 默认层级优先复用，不单独提高 z-index。

## 页面结构

### 全局骨架

公开站：

```text
[Skip link]
[Sticky header: brand | nav | support/theme | account/auth]
[Main: max 1200px, 56/40/80；首页 full-bleed]
[Footer: brand + nav]
[Mobile drawer]
```

控制台：

```text
[Skip link]
[Sidebar 224px: brand | console nav | admin nav | status]
[Workspace]
  [Topbar 72px: menu | support/announcement/theme | return site | admin | logout]
  [Main: 28/24/48]
[Mobile drawer]
```

规则：

- 每个页面只有一个 `h1`；标题层级按 `h1 → h2 → h3` 递进。
- 主内容区域保留 `id="main-content"` 和 `tabindex="-1"`。
- 顶栏不重复品牌文字；控制台无页脚和面包屑。
- 移动端导航进入 Drawer，打开后焦点不出 Drawer。

### 页面模板

| 模板 | 适用页面 | 结构 |
| --- | --- | --- |
| T1 公开内容页 | 模型广场、API 文档 | PageHeader → 筛选/说明 → 内容 → 分页 |
| T2 首页 | `/` | Hero → 能力/展示 → CTA → 页脚 |
| T3 控制台列表 | 任务日志、文本调用、Key、用户、模型 | PageHeader → 筛选条 → 表格/卡片 → 分页 |
| T4 控制台详情 | 账户设置、系统设置 | PageHeader → 信息卡/表单分组 |
| T5 认证页 | 登录、注册 | 品牌侧 + 表单侧（待确认） |
| T6 管理弹窗 | 模型、供应商、用户 | 表单分组 → 校验 → 提交/取消 |

### 页面级要求

#### 首页

- Hero 信息顺序：能力标签（kicker）→ 价值主张（h1）→ 一句说明 → 主 CTA + 次 CTA → 证据条（模型数量、三类能力、按量计费）。
- 品牌名保留在导航和页脚，不作为 h1 的唯一内容。
- 当前没有正式素材时，占位区域必须是“有意设计的占位”（技术网格、渐变遮罩、代码示意），不能是纯灰空块；有素材后再替换。
- 展示区优先使用真实生成结果；没有素材时保留固定比例占位，避免布局跳动。
- 首页只保留一个主 CTA（查看模型广场或创建 Key），其余为次级链接。
- 不新增未经确认的营销区块。

#### 模型广场

- 首屏先给筛选结果摘要（数量、类型、价格单位），再给卡片。
- 卡片顺序：名称与 ID → 能力 chips → 价格主视觉 → 规格/详情入口。
- 价格按“同价同单位合并”展示；金额使用等宽、tabular-nums。
- 长 ID 可复制；不使用省略号遮住 ID 或价格。
- 卡片 hover 只提升边框和底色，不做位移和缩放。

#### API 文档

- 保持现有章节顺序和 hash 深链。
- 每个 endpoint 顶部增加端点条：方法、路径、鉴权、是否异步。
- 桌面右侧增加当前章节导航或参数速览；窄屏折叠到目录。
- 代码块增加语言标签和复制反馈；复制成功用文字提示，不只变图标颜色。
- 状态与错误表保持现有内容，不新增未实现错误码。

#### 仪表盘

- 保留四张统计卡及顺序：可用积分、已用积分、请求次数、今日消耗。
- 以“可用积分”为视觉主卡，其余三项为次级。
- 增加 7 日消耗 sparkline 和最近 5 条任务；均使用 SVG 或现有组件，不引入图表库。
- 低余额提示放在可用积分卡内，不使用全屏警告。

#### 列表页（任务、文本、Key、用户、模型）

- 筛选条位于标题下方；查询与重置成组，重置为次级。
- 表格保持单层外框、横向分隔、8px 圆角，不启用单元格竖线。
- 分页位于表格/卡片下方，默认 20 条，可选 50/100。
- 移动端优先转卡片列表；无法转换时按优先级隐藏次要列。
- 空状态必须说明“为什么空”和“下一步做什么”，不显示无意义插画。

#### 认证页

- 改为左右分栏：左侧品牌、能力说明和安全提示，右侧表单；手机端堆叠为单列。
- 表单保持可见 label，不只依赖 placeholder。
- 错误显示在字段附近，同时保留顶部汇总提示。

#### 管理页

- 表单用控件维护，不要求编辑 JSON；能力与价目保持紧凑分组。
- 凭证不回填；金额使用八位小数字符串。
- 保存与取消成组，保存为主操作；危险操作二次确认。

## 组件规范

### 按钮

| 类型 | 用途 | 视觉 |
| --- | --- | --- |
| Primary | 页面唯一主操作 | 品牌绿底、`--app-on-primary` 文字 |
| Default | 次级操作 | 透明底、`--app-border` 边框 |
| Text/Ghost | 表格行内、辅助操作 | 无边框，hover 使用 `--app-active` |
| Icon | 查看、复制、刷新、下载 | 36×36，移动端 44×44 |

- 高度：32（紧凑）/ 36（常规）/ 40（表单）/ 44（移动端主操作）。
- 加载中禁用并显示 loading；异步操作不能只靠 Toast 告知结果。
- 图标按钮必须有可访问名称；tooltip 只做补充。
- 同一区域最多一个 Primary。

### 输入与选择

- 标签置顶，必填项有明确标记；帮助文本和错误文本靠近控件。
- 高度 36–40；手机端输入字号 16px。
- 日期范围、状态、模型筛选使用统一宽度和间距。
- 错误状态使用失败色边框 + 文本，不只变色。

### 卡片

- 三种形态：flat（边框 + surface）、raised（hover/浮层 + `--shadow-1`）、stat（统计数字）。
- 圆角 8（常规）/ 12（feature 或弹窗）。
- 内边距 20–24；卡片内不再套多层卡片。
- 卡片标题 16–18px，说明 13px；数字使用等宽。

### 表格

- 外框单层，圆角 8；表头使用 `--app-code`，列间无竖线。
- 表头 13px/600，正文 14px；次要列 13px 或 12px。
- 行高约 64–72px；操作列右对齐，图标按钮之间 4–8px。
- 长 ID 可换行或复制，不截断关键信息。
- 超过 10 行时表头吸顶；移动端转卡片列表。
- 空状态、加载骨架、错误重试都在表格区域内展示。

### 状态与标签

| 场景 | 显示 |
| --- | --- |
| 生成任务 `queued/submitting/pending/processing/transferring` | 信息色 + 中文状态 |
| `submission_unknown` | 警告色 +“待核实” |
| `succeeded` | 成功色 +“已完成” |
| `failed` | 失败色 +“已失败” |
| 文本 `processing` | 信息色 +“处理中” |
| 文本 `usage_unknown` | 警告色 +“用量待核实” |

- 状态 Tag 使用低饱和底色 + 前景色，不使用纯色填充大面积。
- 仅颜色不能区分状态；必须同时有文字。
- “无法计算”显示“—”；真实零金额显示八位零，两者不混用。

### 价格与数字

- 账务存储和计算保持八位小数，不改变 `Decimal` 规则。
- 管理表单和详情页显示八位小数字符串。
- 公开模型广场默认显示 2–4 位有效小数，hover/详情显示完整八位。
- 价格数字是卡片主视觉，单位（张、条、秒、百万 token）作为次级信息。
- 不使用科学计数法；不使用二进制浮点数格式化。

### 复制

- 使用图标按钮，点击后立即显示“已复制”文字或 tooltip，1.5 秒后恢复。
- 复制内容不含空格和换行，复制范围明确（Key、ID、URL）。
- 复制结果通过 `aria-live="polite"` 播报。
- 列表和日志不得显示完整 API Key 或摘要，沿用现有安全规则。

### 加载、空状态与错误

- 表格加载：3–5 行骨架，保留表头；不用“加载中”纯文字。
- 卡片加载：标题、数字、说明三段骨架。
- 空状态：图标 → 一句标题 → 一句说明 → 可选主操作。
- 错误：说明发生了什么、用户能做什么；不暴露 SQL、凭证、上游地址。
- 重试按钮只在可安全重试时出现；涉及账务和生成任务时不提供自动重试。

### 分页

- 位于内容下方，左侧显示总数，右侧页码和每页条数。
- 默认 20，可选 20/50/100。
- 本地筛选先筛选后分页；文本日志保持服务端分页。
- 页码按钮不小于 36×36，移动端保持可点击。

### 弹窗与抽屉

- 常规弹窗宽度 520px；宽表单 720–900px；手机最大宽度 `calc(100% - 32px)`。
- 内容超过 70vh 时内部滚动，按钮固定在底部。
- 打开后焦点进入弹窗，关闭后回到触发元素；Esc 可关闭。
- 破坏性操作使用明确动词按钮，不使用“确定”。

### 导航

- 公开站导航保持 3 个主入口；当前页使用文字色 + 字重，不只靠下划线。
- 控制台导航当前项使用 `--app-active` 底 + 品牌绿文字 + 600 字重。
- 导航项最小高度 44px；移动端 Drawer 关闭后焦点回到菜单按钮。
- 客服、主题、公告的图标按钮保持固定顺序，符合“帮助机制位置一致”。

## 验证矩阵

每次界面改动至少检查：

| 维度 | 检查项 |
| --- | --- |
| 主题 | 亮色、暗色、跟随系统；刷新后保持 |
| 宽度 | 375、768、1024、1440；无横向滚动 |
| 键盘 | Tab 顺序、焦点可见、Esc 关闭、Skip link |
| 状态 | 加载、空、错误、成功、待核实 |
| 对比度 | 正文 ≥ 4.5:1；大字号 ≥ 3:1 |
| 动效 | `prefers-reduced-motion` 下不播放 |
| 数据 | 金额、价格、ID、token 不截断、不四舍五入丢精度 |
| 安全 | 不显示完整 Key、摘要、凭证、上游地址或内部成本 |


## 维护方式

- 设计决定只维护在本页；需求规则仍在 [需求与约定](requirements.md)，不在此重复。
- 新增 token 先改本页和 `main.css`，再改组件；禁止组件内直接写一次性值。
- 标注“待确认”的条目在用户确认后改为“已确认”，并同步到需求文档（如涉及业务规则）。
- 第二轮实施完成后，删除已完成条目或移入简短记录，不保留重复的历史清单。
