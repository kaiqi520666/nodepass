## 整体组织

先使用模块化单体。API 与 Worker 共用代码，分别启动；数据库保存任务和账务事实，队列负责执行。

前端官网、用户与管理功能共用工程、登录和主题；官网使用顶部导航，控制台使用独立侧栏布局，由嵌套路由承载。后端保持账号接口、管理接口和兼容 API 的职责区分。菜单与路由控制不代替后端鉴权。

公开模型与价格、API 文档也使用同一前端。匿名访问是访问状态，不增加新的数据库用户角色；公开页面允许直接进入，个人与管理页面分别鉴权。

## 调用关系

```text
外部客户端
  -> OpenAI 兼容 API
  -> API Key 鉴权、参数校验、解析本站模型 ID
  -> 任务及积分业务
  -> Worker
  -> 该模型绑定的供应商适配器
  -> 上游生成、查询
  -> 结果统一转存至本站 OSS
  -> 转存完成，成功结算并交付

用户门户 / 管理后台
  -> 账号及管理 API
  -> 同一套模型、任务、素材、积分业务
```

提交任务时冻结积分，生成结果统一转存至本站 OSS 后认定成功并结算，明确失败释放或退款。上游成功但转存未完成时，不标记本站成功，不结算。

超时后继续查询原任务；迟到的成功结果按相同流程自动转存、交付并结算，不需要管理员逐笔确认。转存失败只恢复转存，不重新生成，也不因转存未完成自动结算或退款。

## 公开目录与接入文档

- 官网首页为 `/`，模型广场为 `/pricing`（保留 `/models` 别名），API 文档为 `/api-docs`；客服二维码使用顶部 Popover，无独立客服页面。上述内容无需登录，登录后仍可浏览。控制台右侧也提供客服 Popover，公告铃铛及时间线弹窗仅在登录后的控制台显示。
- 控制台位于 `/console`，五项菜单分别承载仪表盘、模型定价、API 令牌、任务日志和账户设置；官网账号名链接进入控制台。控制台模型定价与官网模型广场复用模型目录组件及相同公开数据。
- 公开模型与价格使用只读入口，例如 `/api/public/models`，复用模型与价目业务及同一份数据库数据。
- 对外返回明确的公开字段，包括本站模型 ID、类型、能力、分辨率和售价，不直接序列化供应商或管理端完整数据。
- 展示价格与任务报价使用相同的价目匹配规则，后台调整后新查询及时反映；已创建任务继续使用价格快照。
- 同价分辨率可以合并展示，但不能因此隐藏实际计费单位或把不支持的分辨率展示为可用。
- 公开目录不修改 `/v1/models` 等兼容接口的既定鉴权和响应约定；公开价格通过单独的本站接口提供。
- 公开 API 文档只包含开发者已支持的接口及扩展，不直接暴露整站管理接口定义。
- 开发者文档以已实现的 OpenAI 兼容接口为主，标注各接口实际开放状态；本站公开目录仅供价格页读取，不再列入开发者调用示例或公开 OpenAPI 定义，价格通过页面链接查询。
- 通用说明和版本化示例随接口实现维护，具体模型能力与价格读取配置；第一版不建设文档编辑发布平台。
- 公开阅读入口不提供匿名生成、上传、账户或任务数据访问能力。

## 职责边界

- `api` 负责鉴权、请求和响应，不重复实现计费与任务业务。
- `services` 处理业务规则，供 API、Worker 和管理端共同调用。
- `providers` 处理上游鉴权、参数转换、素材准备、提交、查询、状态与错误转换。
- `providers` 不修改用户积分，不自行创建新的本站计费任务。
- `storage` 使用阿里云 OSS 实现文件操作；素材归属、访问权限和保留规则由业务层决定，首期不增加多云存储适配平台。
- `workers` 负责后台执行，重启恢复所需信息必须持久化。
- 数据访问先在对应业务代码中使用 SQLAlchemy，不预先增加通用仓储、插件平台等抽象。

## 最小数据组织

第一版表结构草案包含账号、积分账户、API Key、供应商、模型、价目、任务、素材、任务素材关联、积分流水、兑换码、系统设置和审计，共 13 张表。当前已落地账号、目录、任务、积分流水和系统设置基础表；完整字段、类型、唯一约束和索引统一在[数据库表结构](database-design.md)维护，不在本文重复列出。

一个模型直接关联一个供应商，不增加线路表。任务保留原绑定、请求参数、成本与售价快照，用户资金只按原售价计算；成本估算不冒充已核验实际扣费。账户、任务和不可变流水以数据库事务维持一致。

任务执行、上游执行和积分状态分开记录；超时保留为异常事实而非失败终态。准确流转及崩溃恢复见[任务状态与积分流转](task-lifecycle.md)。

## 最小价格配置

采用有限参数的精确价目与显式默认价，不增加公式、利润率或通用计价引擎。先校验模型能力，再按完整计价组合匹配，未命中时回退默认价，没有有效价则拒绝。

图片每张、视频每条或每秒；不同分辨率可分别定价或使用共用默认价。按秒使用请求指定的合法秒数，不按实际结果改价。成本和售价独立配置，只有售价公开，币种不同不直接相减。

匹配字段、唯一性、示例和金额快照见[数据库表结构的价目设计](database-design.md#6-model_prices)；四位小数舍入、冻结与结算示例见[账务状态及金额](task-lifecycle.md#账务状态及金额)。

## 参数与执行约束

- 视频内部使用模型、提示词、时长、分辨率、画面比例、参考素材等常用参数，具体外部字段按兼容协议核对。
- 参数按模型能力开放和校验，不把示例参数视为每个模型都必须支持的字段。
- 图片数量省略时按一张处理；显式请求其他数量时返回参数错误。
- 超时是需要展示的异常情况，不作为停止后台查询的最终状态；持久化原上游关联及后续查询安排。
- 超时记录、实际查询结果及人工处理记录分开表达，避免继续查询时丢失超时事实。
- 继续查询不等于再次提交生成；迟到成功结果自动转存，完成后自动交付并结算。始终无法确认终态时的查询退出和人工处理规则仍需明确。
- 分开保存上游生成状态和本站转存、交付状态；仅上游成功不能提前暴露本站成功或触发结算。
- 所有生成结果写入本站 OSS，最终交付使用本站持有的结果；输入素材可直接传递合规 HTTPS 地址的规则不变。
- 不增加用户、API Key 或供应商业务限流与配额模块；鉴权、余额检查、请求超时及文件输入限制仍保留。
- 素材、任务和业务记录暂时保留，不为业务数据设置自动删除期限。

## 数据库配置边界

当前已实现供应商、图片模型价目和 OSS 系统设置管理：`/admin/providers`、`/admin/models`、`/admin/settings`。管理接口位于 `/api/admin/providers`、`/api/admin/models`、`/api/admin/settings/oss`，支持 GET、POST、PUT；`GET /api/admin/image-options` 返回按最新沧元章节整理的有限型号能力。全部接口要求管理员网页登录及写请求来源校验，不属于开发者兼容 API。

供应商配置当前仅允许沧元图片和已核对的 HTTPS 接口地址，保存名称、加密密钥、启停、请求超时及查询间隔。OSS 配置通过系统设置保存 Endpoint、Region、Bucket、AccessKey、独立访问域名和对象前缀；Secret 使用独立环境主密钥和 Fernet 加密，响应不包含 Secret 或密文，更新省略 Secret 表示保留。模型、能力、默认参数和价目在同一事务保存，拒绝重复 ID、重复组合、越界金额和不支持的参数；上架要求默认请求有匹配价或默认价。修改现有价目保留 ID，删除的配置价目不再用于新查询。图片受理任务保存绑定与价格快照并冻结积分，尚未接入上游执行和结算。

本轮仅配置静止图片：售价按张、四位小数；成本按张，允许 CNY、USD，按既有表保留最多八位小数。GIF、SVG、视频配置及实际上游提交未实现。预置的是参数校验边界，不是自动上架的模型清单。

建议由后台管理：

- 供应商地址、凭证、适配器选择、启停和请求配置。
- 本站模型 ID、上游映射、能力参数、参数价目、成本价、售价和各自计费单位。
- 上传文件限制、阿里云 OSS 的 Region、Endpoint、Bucket 和业务配置、任务超时和查询间隔。
- 注册开关、网站名称、Logo、公告等常规设置。

部署环境保留数据库、Redis 连接和凭证加密主密钥等引导配置。供应商凭证和需要保存的阿里云 OSS 访问凭证加密入库，后台脱敏展示；凭证和密码不进入请求日志，不要求在文档或聊天中提交真实密钥。

配置必须有类型和范围校验。普通业务配置变更应及时生效；地址、密钥等连接配置变更需要验证，进行中任务的凭证使用策略在实现时明确。

## 对外 API 兼容约束

已确认目标是支持范围内的 OpenAI API 兼容，不是实现其全部产品接口。

当前已实现 `GET /v1/models`、`POST /v1/images/generations` 受理、`GET /v1/images/generations/{id}` 查询，以及图片参数校验/价格匹配/任务建档/积分冻结。Worker 执行沧元异步提交和查询，结果转存本站 OSS 后结算，明确失败释放；编辑、视频和素材输入仍未实现。

- `/v1/models` 通过 `Authorization: Bearer <本站 API Key>` 鉴权，不接受网页 Cookie 或网页登录令牌替代；每次查询验证 Key 和账户均为启用状态，并记录最近使用时间。
- 正常响应为 `{"object":"list","data":[...]}`；每个模型仅包含 `id`、`object: "model"`、Unix 秒级 `created` 和本站标识 `owned_by: "nodepass"`。与公开价格页共用上架、供应商启用和存在价目的筛选条件，不返回价格、成本或上游映射。
- `/v1/` 的鉴权、路由、校验和服务错误统一为 `error` 对象，包含 `message`、`type`、`param`、`code`；认证错误返回 401 和 `invalid_api_key`，不回显凭证、SQL 或内部异常。
- API Key 由已登录用户在控制台“API 令牌”页创建、查看、复制、编辑和删除；摘要用于认证，原文以 Fernet 加密保存，过期时间可选。网页会话不具备直接调用兼容 API 的权限，API Key 不具备账号管理权限。
- Key 管理使用本站 Cookie 鉴权及来源校验，只能访问当前用户自己的记录；删除立即失效并移除记录。管理员可在用户管理每行的“操作”菜单中进入积分调整或修改密码；积分变更写入流水并按四位小数处理，密码使用现有安全哈希策略保存。
- 任务日志返回任务 ID、类型、模型、状态、耗时、消耗积分、请求参数和错误信息；用户可查看或下载已转存结果、查看详情。任务记录暂不提供用户删除入口，历史任务和账务流水保留。
- 模型列表和认证错误已通过 OpenAI Python SDK 的本地测试，SDK 仅为测试依赖；图片和视频接口的 SDK 验收仍待接入。
- `POST /v1/images/generations` 返回 `202` 和本站任务 ID；需要运行 `python -m app.worker` 执行后台提交、轮询、转存和结算。`GET /v1/images/generations/{id}` 返回当前状态及本站结果地址。

协议参考：[OpenAI 模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)、[鉴权](https://developers.openai.com/api/reference/overview#authentication)。本轮仅核验模型列表，不据此宣称其他接口兼容。

- 对外使用本站 API Key 进行 Bearer 鉴权。
- 请求中的 `model` 使用本站唯一模型 ID，内部转换为上游模型 ID。
- 对外接口的路径、请求编码、字段、响应和错误格式须按选定协议核对。
- 兼容响应不额外包装本站的 `code/message/data` 外壳。
- 图片兼容接口不能直接用内部任务编号替代协议规定的生成结果。
- 内部可以使用 Worker；图片 HTTP 返回时机、流式能力及超时响应按选定接口确认。
- 视频采用创建、查询、结果获取的任务流程，具体兼容基线和 SDK 版本待核验。
- 超出兼容范围的上游参数必须明确记录为扩展，不静默丢弃参数或降低生成要求。
- 素材上传、用户账户、兑换和管理接口单独定义，不伪装成官方标准接口。

之前讨论过的候选接口包括模型列表、图片生成与编辑、视频创建与查询及内容下载。它们仍需形成逐项接口清单并验证，本文不将旧会话中的官方服务状态或停用日期描述作为已核验事实。

## 必须保留的实现约束

- 用户只能访问自己的素材、任务和账务；管理员权限由后端校验。
- 外部 URL 的获取需要校验协议、目标地址及重定向，限制大小和下载时间，防止访问内部网络。
- 兑换、扣费、退款和人工处理需要幂等，避免重复请求导致重复记账。
- 积分冻结需要与可用余额校验保持事务一致性，避免并发请求超额冻结。
- 提交受理不明时不得盲目重新生成；转存失败只恢复转存。
- 超时核查保留原上游关联，不自动改绑供应商。
- 日志应脱敏，不记录可直接使用的密钥和完整媒体内容。
- 结算以本站 OSS 转存完成为前提，按请求指定秒数和原价目快照计费；迟到结果也走同一条幂等交付与结算流程。
