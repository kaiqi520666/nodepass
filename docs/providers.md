### 系列与具体上游模型

图片当前接入目标为 `gpt-image-2`、`gpt-image-2.5`、`gpt-image-2.6` 三个系列；系列名不等同于一个覆盖全部能力的上游模型 ID。

| 系列 | 章节列出的具体型号 | 配置区别 |
| --- | --- | --- |
| GPT Image 2 | `gpt-image-2`、`gpt-image-2-1k`、`gpt-image-2-2k`、`gpt-image-2-4k`；另说明 `gpt-image-2-x` | 基础名为 web；带 k 的名字固定像素档；`-x` 用 `tier` 选档，不使用 `series` |
| GPT Image 2.5 | `gpt-image-2.5`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`，以及 flare、sunburst 各自的 `-1k`、`-2k`、`-4k`；另说明 `gpt-image-2.5-x` | 基础名和不带 k 的分支名为 web；`-x` 必填 `series=flare/sunburst`，并用 `tier` 选档 |
| GPT Image 2.6 | `gpt-image-2.6`、`gpt-image-2.6-flare`、`gpt-image-2.6-sunburst`，以及 flare、sunburst 各自的 `-1k`、`-2k`、`-4k`；另说明 `gpt-image-2.6-x` | 静止图的分支、档位规则与 2.5 类似；章节另列 GIF、SVG，不能当成三个系列的共同能力 |

Flare、Sunburst 是供应商文档区分的模型分支，不作为摄影、插画等画风选项。具体选哪个上游公共名、是否使用 `-x`，仍需在配置和验证时明确，不自动将本站三个系列名绑定至某个上游型号。

保持一个本站模型 ID 绑定一个具体上游模型 ID。固定档位型号分别配置；只有明确选用支持 `tier`、`series` 的 `-x` 型号时，才允许通过这些参数选择能力，不根据请求参数偷偷切换成另一个上游模型 ID。不在代码或迁移中预置正式上架名单。

### 通信与任务

- 章节示例使用 `https://direct-api.cangyuansuanli.cn` 和 Bearer API 令牌。
- 文生图为 `POST /v1/images/generations`；编辑为 `POST /v1/images/edits`，编码与字段按所选模型和操作核验。
- 显式提交 `async: true`。章节虽称“默认异步”，同时说明省略或传 false 是同步兼容，因此适配器不能依赖省略值。
- 三个章节均指向 `GET /v1/images/generations/{id}` 查询图片任务，包含编辑任务；旧版“在原创建路径后追加任务 ID”的推断不再作为当前基线。
- 章节给出 `/v1/images/generations/{id}/content` 取文件，以及完成响应中的结果 URL；具体回包、下载鉴权、重定向及有效期仍需验证。
- 章节示例的轮询间隔有 3–5 秒、4 秒、5–10 秒等不同说法。建议初期将 5–10 秒作为后台可配置的查询间隔，最终以实际账号要求核验；这不是本站用户调用配额。
- 章节说明同步调用可能耗时较长且断连后仍可能产生结果和扣费。本站内部继续采用提交、查询、转存流程；受理不明不重提，转存失败不重新生成。
- 供应商的异步任务接口属于其协议，不能据此将图片任务 ID 响应标成 OpenAI 标准。本站对外兼容接口的请求、响应和扩展仍按[架构约束](architecture.md#对外-api-兼容约束)单独核对。

### 参数能力与差异

| 参数或能力 | 当前章节说明 | 本站处理 |
| --- | --- | --- |
| `model`、`prompt` | 三系列共同字段 | 校验本站模型，适配器转换上游 ID |
| `n` | GPT Image 2 基础 web 名写明 1–10；静止图带 k 和 `-x` 为 1 | 本站始终只允许 1，不随上游放开多张 |
| `quality` | 不带 k 的基础 web 名及 flare、sunburst web 名不传；带 k 和 `-x` 列出 low、medium、high、xhigh、max | 按具体型号开放，不统一发送默认质量 |
| `tier` | 仅 `-x`；web、1k、2k、4k，省略按 web | 仅为支持该字段的型号配置，报价前补齐默认值 |
| `series` | 仅 2.5、2.6 的 `-x`；必填 flare 或 sunburst | 不套用到 2，也不套用到名字已含分支的型号 |
| `size` | 支持的型号使用比例或 `宽x高`；2.5、2.6 基础 web 名不可套用带 k 或 `-x` 的字段 | 依据型号能力校验，不传 `aspect_ratio` 或 `ratio` |
| `images` | 静止图参考图使用 HTTPS URL 数组；2 章节写最多 9 张，2.5、2.6 带 k 最多 16 张、`-x` 最多 9 张 | 不全局固定为 9 张，不直接向上游传单数 `image`；编码转换另行核验 |
| `mask` | 管理员确认当前数据库的全部图片模型支持 mask | `supports_mask` 由数据库和后台开关控制，不按型号名禁用；请求编码及素材约束仍需接入核验 |
| `background` | 相关型号列出 auto、opaque、transparent | 只在型号明确支持时开放 |
| `output_format` | 静止图仅带 k 列出 png、jpeg、webp；不套用到 `-x` 或基础 web 名 | 按具体型号校验，不能全局开放 |
| `response_format` | url 或 b64_json | 异步两种实际响应及本站输出映射仍需验证 |
| GIF、SVG | 仅 2.6 章节列出；GIF 有独立帧数、帧时长，参考图结构为 `images[].image_url` | 建议首期先做静止图，不自动开放 GIF、SVG；是否纳入后续范围待用户确认 |

带 k 的三个系列采用章节列出的相同像素预算：1K 方图 1024×1024、2K 方图 2048×2048、4K 方图 2880×2880；自定义尺寸要求 16 对齐、最长边不超过 3840、宽高比不超过 3:1、像素不少于 655360，各档上限分别为 1048576、4194304、8294400。不能将“4K”统一解释为 3840×2160，也不将带 k 的规则套用到 web 或 `-x`。`-x` 的尺寸限制需单独确认。

未核验的 2.5、2.6 web 型号参考图上限在型号选项中使用 `null` 表示未知，不将未知写成上游上限 0；管理员可在本站配置 0–16 张并存入数据库，已核验型号仍受其 9 / 16 张上限约束。本站配置不代表已经实测通过上游参考图编辑；`gpt-image-2.5-flare` 的本站上限由管理员指定为 16 张。

GPT Image 2 章节另列 JSON 请求体最多 8 MiB、Base64 参考图解码后合计最多 5 MiB；同一页对 Base64 与 HTTPS 素材的描述并不完全一致，不能把这些限制不经核验推广到全部型号。本站不设业务调用配额，不等于可以绕过协议的输入体积和素材约束。

临时验证脚本仅用 Python 标准库，十项离线检查通过；脚本、密钥、任务标识、原始响应和图片均不纳入项目，仅保留本节脱敏结论。上游生成成功不等于本站交付成功，正式接入仍须完成 OSS 转存后才能结算。

## 本项目的接入范围

- 图片第一阶段只接沧元。
- 视频围绕四家实际支持的模型接入，具体上架由管理员决定。
- 不硬编码“首批模型名单”，也不在用户侧展示未配置的模型。
- 每个本站模型直接绑定一个供应商及上游模型 ID。
- 供应商协议使用独立适配代码；同一协议确实能够复用时再共享实现。
- 新模型若需要现有适配器没有覆盖的操作或字段，需要先扩充代码并验证，不能只靠后台填名称就宣称支持。
- 图片每次只生成一张；视频使用统一常用参数，由适配器映射上游字段并校验模型能力。
- 图片、视频的配置成本价与用户售价分开记录，由管理员在本站后台维护；配置成本不能直接标记为上游已发生的实际扣费。视频支持按次（每条）或按秒，按秒以用户提交并通过模型能力校验的秒数计费。

## 适配器职责

每家按真实需求实现以下能力：

1. 使用供应商配置构造鉴权和请求。
2. 将本站模型 ID 对应的参数转换为上游参数。
3. 将本站上传素材或外部 URL 转成上游要求的 URL、Base64 或上游素材 ID，并保留用途与顺序。
4. 提交生成，解析上游任务编号或直接返回的结果。
5. 查询任务，将状态、错误和用量转换为内部格式。
6. 提供获取结果所必需的地址、鉴权或下载方式。

取消、回调、原请求恢复、余额查询等能力按实际需要增加，不要求每家实现不存在的接口。供应商没有取消能力时，本站不能仅停止查询就声称上游任务已取消。

适配器不自行扣减用户积分，不擅自切换供应商，也不在受理结果未知时重新提交。

## 素材与结果

- 上传素材和外部 URL 都需要经过本站权限及输入校验。
- 各供应商要求的素材读取方式由适配器转换，本站素材记录不绑定某一家上游格式。
- 上游支持 HTTPS 素材地址时直接传递，不强制先转存；需要 Base64 时由本站获取文件并转换。
- 本站上传文件按上游需要提供可读取的 HTTPS 地址或 Base64；上游素材入库等特殊要求仍由适配器处理。
- 获取外部文件进行转换时保留目标地址、重定向、大小、类型和下载超时校验。
- 本站素材、任务和业务记录暂时保留，不实施 24 小时自动删除；供应商结果链接有效期仍需核验。
- 所有生成结果统一转存至本站 OSS，转存完成后才交付并结算；供应商返回 URL、Base64 或鉴权下载时，分别按真实格式获取并存储，不能直接交付供应商临时地址代替转存。
- 超时后收到成功结果也自动转存、交付并结算；本站存储已确定使用阿里云 OSS，下载授权方式和具体接入参数在接口设计阶段落实。
- 第二家 IP 站目前提供的是 HTTP 文档地址，实际调用地址和凭证传输方式需要另行核验。

## 上架验证

每种实际支持的协议和生成方式至少覆盖：

- 正常提交、查询、获取结果和本站模型 ID 转换。
- 无效参数、不支持能力和供应商明确拒绝。
- 提交超时且受理不明、查询中断、进程重启后的任务恢复。
- 生成成功但转存失败后的恢复，确保不重新生成、不提前标记本站成功或结算，转存完成后仅结算一次。
- 图片每次仅一张，拒绝其他数量；视频分辨率、计费单位、价目和时长口径与规则一致。
- 本站上传和外部 URL 的实际可用性。
- 后台修改模型或价格后，旧任务仍使用已记录的业务信息。
- 超时后仍继续查询原上游任务，不重复生成；迟到成功结果自动转存、交付并结算，管理员核实与资金操作不重复执行。

验证记录应注明供应商、模型、参数组合、日期及结果，并对凭证和素材信息脱敏。上游付费生成应在用户授权后进行。
