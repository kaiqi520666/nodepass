# UI/UX Pro Max 使用与界面规范

整理日期：2026-11-07。记录设计技能在 NodePass 中的使用方式，以及界面实施约定；已拆分官网与控制台布局，保留账号、公开模型与文档、只读用户管理及三态主题。首页图片和视频暂用占位，任务日志尚未接入。

## 文档与技能的关系

- 项目本地技能入口为 [UI/UX Pro Max SKILL.md](../.agents/skills/ui-ux-pro-max/SKILL.md)，包含规则、数据目录和查询工具。
- 本文件记录项目适用范围和约束，不复制整份技能，也不修改其原始文件。
- 使用时以用户最新决定、[需求确认](requirements.md)和[技术栈](tech-stack.md)为约束，再选择适用的技能建议。
- 本技能用于布局、配色、字体、表单、表格、导航、反馈、响应式和可访问性，不负责后端业务规则。

## 项目固定边界

| 事项 | 项目约定 |
| --- | --- |
| 框架与组件 | Vue 3、Element Plus |
| 图标 | `@element-plus/icons-vue`；供应商和模型 Logo 使用对应素材 |
| 产品界面 | 同一工程、登录和主题；官网使用顶部导航，控制台使用独立侧栏布局 |
| 权限 | 公开页面允许访客访问；账号角色为普通用户、管理员，管理员拥有普通用户功能 |
| 主题 | 明亮、暗黑、跟随系统 |
| 范围 | 官网首页、模型广场、API 文档、联系客服及注册登录；不做网页创作台，不额外扩充业务模块 |

技能中部分章节面向 React、移动端或 OLED 风格，其默认框架、图标和设备规范不能直接替代项目选型。品牌主色、具体字号和视觉细节在页面设计时确定，不将数据集推荐自动视为已确认方案。

## 使用流程

1. 先读取需求、技术栈、本文件，以及相关页面的业务规则。
2. 新页面或全局视觉方向使用设计系统查询；具体组件问题使用一个聚焦领域查询；Vue 实现问题使用 Vue 查询。
3. 检查查询结果是否适合桌面 Web、Element Plus 和本项目业务。结果为空或不相关时改写一次；仍无匹配则明确说明，并使用官方组件文档及适用的通用规则。
4. 将适用建议落实到现有 Element Plus 组件、共用布局和主题变量中。
5. 页面完成后检查权限展示、明暗主题、交互状态和不同窗口尺寸。

从项目根目录执行的查询示例：

```bash
# 新页面的整体视觉建议
python3 .agents/skills/ui-ux-pro-max/scripts/search.py "developer API dashboard minimal" --design-system -p "NodePass"

# 聚焦表单错误展示
python3 .agents/skills/ui-ux-pro-max/scripts/search.py "error summary validation" --domain ux

# Vue 实现建议
python3 .agents/skills/ui-ux-pro-max/scripts/search.py "form validation" --stack vue
```

示例用于查询，不表示已经生成或确认视觉方案。先检查结果，不默认使用 `--persist` 创建另一份重复规范，也不依据查询结果自动安装依赖。

## 官网、控制台与权限

- 一个 Vue 工程、一套登录入口，两套布局，通过嵌套路由归属页面。
- 官网顶部导航为首页、模型广场、API 文档；右侧集中放置客服、主题及带小图标的注册登录入口，不显示公告。
- 官网和控制台共用客服组件，点击展开 Element Plus Popover，放置正方形二维码占位，不另设客服页面。控制台右侧放置客服、公告铃铛与主题；公告只在登录后的控制台显示，点击打开 Dialog，使用 Timeline 呈现公告，当前仅展示“暂无公告”，未接入公告数据或后台配置。
- 登录后官网显示账号名，点击进入控制台；不因为已登录就将公开页面重定向到控制台。当前账号名展示邮箱用户名部分，完整邮箱在账户设置查看。
- 控制台顶部不显示账号名；“返回官网”和管理员的“用户管理”入口采用带图标的按钮样式，窄屏仅显示图标并保留可访问名称，退出按钮独立保留。仪表盘统计下方不重复放置模型定价、API 令牌和 API 文档快捷链接。
- 控制台侧栏仅提供仪表盘、模型定价、API 令牌、任务日志、账户设置；令牌管理独立于账户设置。
- 任务日志使用筛选工具栏（任务 ID、图片/视频、状态、模型、日期），表格展示任务信息、类型、模型、状态、耗时和消耗积分；结果提供查看/下载，详情使用文字按钮；任务记录暂不提供用户删除入口。
- 控制台布局不设页脚，官网保留页脚；页面不展示“1 元 = 1 积分”兑换提示。
- 控制台不显示面包屑，顶部不重复展示 NodePass 文字，保留侧栏品牌与手机导航按钮；页面以主标题和侧栏选中项定位；内容区使用剩余全部宽度，不设置居中最大宽度，桌面保留 24px、手机保留 18px 左右边距。
- 仪表盘依次展示可用积分、已用积分、请求次数、今日消耗四张统计卡片，桌面四列、较窄窗口两列、手机单列。可用积分使用真实余额；其余三项在统计接入前显示“—”，不将未知数据展示为零。冻结积分仍可在账户设置查看。
- 账户设置使用两张积分卡片展示可用、冻结积分；邮箱、账户 ID、身份、注册时间各使用独立信息卡片，桌面两列、手机单列，统一 8px 圆角与图标。不新增账户编辑能力。API 令牌页按名称、密钥、状态、创建时间、过期时间和操作展示，密钥提供查看/复制按钮，操作提供编辑/删除。
- 管理员侧栏及移动导航单独提供“管理”区，包含用户管理、供应商配置、模型与价格，不占普通用户的五项菜单。
- 供应商和图片模型采用列表与表单弹窗；供应商密钥使用密码框且不回填，成本和售价独立填写，积分金额保留字符串输入与四位小数校验。用户管理每行统一使用“操作”按钮，菜单提供“积分调整”和“修改密码”；积分调整在弹窗内选择增加或扣除，并要求金额和备注。能力参数使用选项和默认值选择，价目可使用默认价或完整参数组合，不要求管理员编辑 JSON。
- 管理模型表格展示可读名称、可复制的本站模型 ID、档位、供应商、实际成本、售价和上架状态；上游模型 ID 在编辑弹窗查看。支持搜索及系列、档位、状态筛选。同价质量按实际价格合并，成本与售价分别分组；点击价格展开完整参数价目。金额至少展示四位小数，成本保留超过四位的有效精度并注明币种，不修改数据库中的模型名称和价格。
- 官网不展示控制台面包屑、服务连接状态和侧栏。首页图片、视频先使用固定比例占位，具体素材及视觉方案后续讨论。
- 公开页面允许访客访问；控制台父路由要求登录，管理父路由额外要求管理员身份。
- 管理员继承普通用户功能，无须切换身份或重新登录。
- “我的余额”“我的调用”等页面始终展示当前账号数据，全站数据通过管理功能查看。
- 后端管理接口和数据访问独立鉴权，菜单隐藏不承担安全边界。

## 公开模型与 API 文档页面

- 模型与价格使用可扫描的列表或表格，支持区分图片、视频，方便复制本站模型 ID 和查看对应能力。
- 官网模型广场与控制台模型定价共用目录组件：以模型卡片展示可复制的模型 ID、计价条件、实际单价和参数入口，避免固定表格列造成大片空白；仅在后台显示名称不同于 ID 时另展示该名称。卡片不重复标注图片 / 视频，不重复推导型号名称；参考图、比例和格式等能力在详情弹窗按字段展示。相同价格和计费单位的参数组合合并展示，quality 使用实际值（如 `low / medium / high`、`xhigh / max`），不另起“常规 / 高质量”名称；条件与价格放在同一价格单元内，价格保留四位小数，不同计费单位不合并。详情保留完整价目，不展示供应商映射或成本。官网支持类型、系列、档位和名称 / ID 筛选；控制台模型定价按 `gpt-image-2`、`gpt-image-2.5`、`gpt-image-2.6` 三个系列切换。
- 官网模型目录使用“全部 / 图片 / 视频”分段切换，各选项带统一图标，控件使用 8px 外圆角、细边框、固定选项高度和清晰的选中背景；控制台使用三个图片系列分段切换。官网和控制台共用卡片样式，保留原生键盘操作和筛选逻辑。
- 视频价格明确列出分辨率、按次或按秒单位；同价分辨率可合并显示，价格统一从后台配置读取。
- API 文档提供清晰的接口目录、参数表、请求响应示例、错误和计费说明，便于复制接入示例。
- 公开文档阅读不要求输入 API Key，不默认提供在线付费试调功能。
- 未配置模型、模型下架、价格加载失败等情况有明确反馈，不展示虚构模型或报价。
- 公开页面适配三态主题和窄屏；长模型 ID、代码示例和价格表不能撑破页面。

## 主题实施约定

- 模式值为 `light`、`dark`、`system`，实际配色只有明亮和暗黑。
- 默认 `system`；Pinia 保存运行时状态，当前浏览器 `localStorage` 保存用户选择。
- 主题属于个人设备偏好，首期不增加数据库偏好表或跨设备同步。
- 使用 Element Plus 暗黑 CSS，以根元素的 `dark` 类控制；自定义区域复用语义颜色变量。
- 使用 `matchMedia('(prefers-color-scheme: dark)')` 读取并监听系统配色，仅在 `system` 模式响应系统变化。
- 手动选择明亮或暗黑时，系统变化不覆盖选择。
- 首屏绘制前恢复主题，尽量避免闪烁；无效配置或存储不可用时回退到跟随系统。
- 登录、注册和所有业务页面使用同一主题逻辑；弹窗、下拉菜单、提示等浮层也要适配。
- 共用导航用图标加菜单展示三个明确选项，使用 Element Plus 图标，不增加主题切换库。

此前技能检索未找到 Vue + Element Plus 三态主题的具体实现匹配。实施方法参考 [Element Plus 暗黑模式](https://element-plus.org/zh-CN/guide/dark-mode)、浏览器 [matchMedia](https://developer.mozilla.org/en-US/docs/Web/API/Window/matchMedia)和[配色变化事件](https://developer.mozilla.org/en-US/docs/Web/API/MediaQueryList/change_event)文档。

## 界面规则

- 围绕公开模型价格、API 文档、API Key、余额、调用记录和管理表格组织页面，优先保证信息清晰和操作效率。
- 常用操作使用现有组件；相同字段和业务状态保持一致的名称、格式和反馈。
- 所有现有表格统一使用 `AppTable.vue`，分页使用 `AppPagination.vue`；不启用 Element Plus `border`，保留单层外框和横向行分隔线，不显示竖线，表格外框使用 8px 圆角。表头使用浅底色，统一留白与行距，行悬停和键盘聚焦使用中性色背景，操作按钮按需显示边框；加载、空状态和明暗主题共用样式，窄屏在表格内部横向滚动。数据列表默认每页 20 条，可选 50、100 条；本地列表先筛选后分页，用户管理使用后端分页，切换每页条数回到第一页。API 文档的字段说明表不分页。
- 页面标题统一使用 `PageHeader.vue`，由分区眉题、主标题、左侧色标和右侧操作插槽组成；所有使用该组件的页面统一显示左侧竖线，标题下方不额外增加分隔线。各页面不再重复书写标题结构，移动端操作区可换行。
- 颜色、边框、间距和字号使用统一变量或现有组件规范，不额外建立多层设计令牌平台。
- 积分按四位小数展示，价格注明按张、按次或按秒；具体结算规则仍以需求文档为准。
- 表单有明确标签、字段错误和提交反馈；请求中、空数据、失败和无权限均有对应状态。
- 图标按钮有可访问名称，陌生图标提供提示；状态不能仅靠颜色区分。
- 长模型 ID、URL 和表格内容提供合理换行、复制或完整查看方式，不让内容撑破布局。
- 明暗两种主题分别检查文字、边框、焦点和反馈的可读性；不使用整页反色代替主题适配。
- 窄屏保持主要功能可操作，桌面表格保持合适信息密度。

## 页面验收

- 未登录可直接阅读模型价格和 API 文档；个人页面与管理页面仍要求对应权限。
- 官网与控制台采用不同布局，登录后仍能浏览官网；点击官网账号名进入控制台，控制台提供返回官网入口。
- 公开模型、能力和价格与后台配置一致，单位明确，不泄露成本、凭证、内部映射和个人数据。
- 普通用户看不到管理菜单，直接访问管理路由被拦截；管理员可使用全部对应功能。
- 主题手动切换生效，刷新恢复，跟随系统可实时响应，手动模式不被系统变化覆盖。
- 路由切换、登录注册、表格、表单、弹窗、下拉和提示的主题一致。
- 键盘焦点可见，图标按钮有名称，输入错误明确，加载与失败状态可恢复。
- 在常用桌面和窄屏尺寸检查遮挡、溢出、长文本及布局跳动。

该清单用于后续实施验收，不表示当前页面已经开发或验证。
